# Lab 12: 환경 센서 로깅 (M4 AHT20+BMP280 → M55 → ST7789V3 컬러 TFT)

M4가 온습도 센서 AHT20과 기압 센서 BMP280이 함께 실장된 콤보 모듈을 I2C로 읽어 M55로
보내고, M55는 그 값을 SPI로 연결된 1.69인치 240x280 ST7789V3 컬러 TFT 패널에 실시간으로
표시하는 랩입니다. Lab 11이 "센서 하나, 정상 동작만 가정"이었다면, 이 랩은 처음으로
**센서가 두 개이고, 그중 하나가 없거나 도중에 응답을 멈출 수 있다는 것까지 감안한 설계**를
다룹니다.

이 문서는 이 랩 하나만 열어도 처음부터 끝까지 빌드/배선/이해가 가능하도록, 다른 랩(Lab 09,
Lab 11)과 공유하는 배경 설명(TFT 하드웨어, raw-SPI 드라이버 구조 등)도 여기 다시
풀어씁니다.

## 학습 목표

- 부팅 시 I2C 버스를 스캔해 센서의 실제 주소를 자동으로 찾아내는 패턴을 이해한다 (모듈마다
  주소가 다를 수 있는 실제 하드웨어 상황에 대응).
- 서로 다른 두 센서(AHT20/BMP280)를 하나의 IPC 메시지로 합쳐 보내고, 한쪽 센서가 없거나
  실패했을 때 다른 센서로 대체(fallback)하는 설계를 이해한다.
- "1초 평균값을 주기적으로 보낸다"는 기본 동작과, "값이 급격히 튀면 즉시 보낸다"는 예외
  동작을 하나의 프로토콜 안에 함께 설계하는 방법을 익힌다.
- **연결 끊김**(mbox 메시지 자체가 안 옴)과 **센서 에러**(mbox는 정상인데 특정 센서 값만
  못 읽음)가 서로 다른 두 가지 장애라는 것을 구분하고, 화면에도 별도로 표시하는 설계를
  익힌다.
- Lab 09/11에서 확립한 "센서 텔레메트리 → mbox → ISR/큐/워커스레드" 패턴, 그리고 Lab
  11에서 확립한 "raw SPI로 ST7789V3 TFT 구동" 패턴을 함께 재사용한다.

## 이전 랩과의 연결

Lab 11은 M4가 온보드 가속도계 하나만 읽어 M55의 TFT에 뿌리는 구조였습니다. 이 랩은 M55 쪽
TFT 구동 코드(패널 초기화, 폰트, SPI 청크 전송 등)는 Lab 11 것을 그대로 재사용하고, M4
쪽은 완전히 새로 작성했습니다 — 온보드 센서 대신 **외부 배선된 AHT20+BMP280 콤보 모듈**을
읽고, 단일 센서/단일 값이 아니라 **두 센서, 세 가지 값(온도/습도/기압), 두 가지 전송
방식(평균값 + 즉시 알림)** 을 다루기 때문입니다.

## 핵심 개념

### 1. 왜 Zephyr 센서 서브시스템 대신 raw I2C를 쓰는가

Zephyr는 `sensor_sample_fetch()`/`sensor_channel_get()`으로 대표되는 표준 센서
서브시스템과, AHT20/BME280용 in-tree 드라이버를 제공합니다. 이 랩은 일부러 그 경로를 쓰지
않고 `i2c_write()`/`i2c_read()`/`i2c_write_read()`를 직접 호출하는 방식을 택했습니다.
이유는 두 가지입니다.

1. **부팅 시 주소 자동 스캔이 필요함.** Zephyr 센서 서브시스템은 devicetree에 센서 노드를
   `aht20@38` 처럼 **고정 주소**로 선언해야 합니다. 그런데 이 랩의 요구사항은 "실제 모듈마다
   주소가 다를 수 있으니 부팅 때 스캔해서 자동으로 찾으라"는 것이라, 고정 주소를 전제하는
   방식과는 맞지 않습니다. BMP280은 특히 SDO 핀 배선에 따라 0x76 또는 0x77 둘 중 하나로
   갈립니다.
2. **드라이버 Kconfig 심볼명 불확실성 회피.** 이 프로젝트가 쓰는 Zephyr 버전에서
   `CONFIG_AHT20`/`CONFIG_BMP280` 같은 심볼이 정확히 어떤 이름인지 사전에 확신할 수
   없었고(Lab 11에서 `CFB_SHELL` 심볼이 아예 존재하지 않아 겪었던 것과 같은 종류의 문제),
   raw I2C는 이 불확실성을 완전히 없애줍니다.

대신 두 센서의 초기화/측정 명령 시퀀스를 각 데이터시트대로 애플리케이션 코드에서 직접
구현해야 합니다 (`aht20_read()`, `bmp280_read()` 등).

### 2. AHT20 프로토콜 (고정 주소 0x38)

AHT20은 칩ID 레지스터가 없어서, "이 주소에 뭔가 응답하는가"만으로 존재를 확인합니다.

- 소프트 리셋: `0xBA` 전송 후 20ms 대기.
- 초기화: `0xBE 0x08 0x00` 전송 후 10ms 대기.
- 측정: `0xAC 0x33 0x00` 전송 → 80ms 대기 → 6바이트 읽기.
  - 1바이트째: 상태 바이트 (최상위 비트가 1이면 "measuring busy" → 에러로 취급).
  - 2~4바이트: 20비트 습도 원시값 (`raw_hum / 2^20 * 100` = 습도 %).
  - 4~6바이트: 20비트 온도 원시값 (`raw_temp / 2^20 * 200 - 50` = 온도 °C).

부동소수점 없이 `%`/`°C`를 milli 단위(1000배) 정수로 바로 스케일링해서 계산합니다.

### 3. BMP280 프로토콜 (주소 0x76 또는 0x77)

- 칩ID 레지스터(`0xD0`)를 읽어 `0x58`(BMP280) 또는 `0x60`(BME280, 습도 기능만 다르고
  레지스터 맵은 호환)이면 존재로 인정합니다.
- 보정 계수 24바이트(`0x88`~`0x9F`, 리틀엔디안)를 읽어 `dig_T1~T3`, `dig_P1~P9`에 저장합니다
  — 이 계수는 칩마다 공장에서 다르게 캘리브레이션되어 있어서, 원시값을 실제 온도/기압으로
  환산하려면 반드시 필요합니다.
- `ctrl_meas`(`0xF4`) = `0x27` (온도/기압 오버샘플링 x1, normal 모드), `config`(`0xF5`) =
  `0x00` (내부 스탠바이/필터는 꺼둠 — 어차피 200ms 주기로 우리가 직접 폴링하므로 불필요)로
  설정해 측정을 시작시킵니다.
- `0xF7`~`0xFC`에서 20비트 원시 기압/온도값을 읽고, Bosch 데이터시트의 표준 64비트 정수
  보정 공식(`bmp280_compensate_temp()`, `bmp280_compensate_pressure()`)으로 실제 값으로
  환산합니다.

> **참고**: 이 보정 공식과 명령 시퀀스는 공개 데이터시트를 그대로 옮긴 것이며, 실기
> 검증을 통해 정상 동작을 확인했습니다. 기압이 950~1050 hPa 범위를 크게 벗어나거나
> 온도가 기준 온도계와 1~2도 이상 차이 나면 `dig_*` 계수를 읽는 부분부터 의심하세요.

### 4. 두 센서를 하나의 값으로 합치는 방법 (Fallback)

이 모듈은 AHT20(온습도)과 BMP280(기압+자체 온도)이 둘 다 온도를 측정할 수 있습니다. 이
랩의 규칙은 다음과 같습니다.

- **AHT20이 있고 정상 응답하면** → AHT20의 온도를 사용합니다 (습도까지 함께 얻을 수 있는
  쪽이 우선).
- **AHT20이 없거나, 있어도 이번 주기에 읽기 실패하면** → BMP280의 온도를 대신 사용합니다.
  화면에는 이 경우 `T:23.5C(bmp)`처럼 출처를 표시해, "AHT20 값이 아니라 BMP280에서 대신
  가져온 값"임을 알 수 있게 합니다.
- **습도**는 AHT20만 측정할 수 있으므로 대체 수단이 없습니다. AHT20이 없거나 실패하면
  화면에 `H:N/A`(애초에 없음) 또는 `H:ERR`(있었는데 지금 실패)로 구분해 표시합니다.
- **기압**도 BMP280만 측정할 수 있으므로 마찬가지로 대체 수단이 없습니다.

### 5. 200ms 샘플링 → 1초 평균, 그리고 급변 시 즉시 알림

M4는 200ms마다 두 센서를 모두 읽습니다(요청 사항: "센서들은 200ms 단위로 스캔"). 5번
샘플링할 때마다(200ms × 5 = 1초) 그동안의 평균값을 계산해 `IPC12_REASON_PERIODIC`
메시지로 보냅니다. 평균은 방향성 없는 노이즈를 걸러주지만, **온도/기압이 실제로 급하게
바뀌는 상황**(예: 문을 열어서 실온이 갑자기 변함)을 최대 1초까지 늦게 알리게 되는 단점이
있습니다. 그래서 이 랩은 매 200ms 샘플마다, 마지막으로 M55에 실제로 통보한 값과 비교해:

- 온도가 ±0.5°C 이상 벗어나면 → 그 즉시 `IPC12_REASON_TEMP_JUMP` 메시지를 별도로 보냅니다.
- 기압이 ±50hPa 이상 벗어나면 → 그 즉시 `IPC12_REASON_PRESSURE_JUMP` 메시지를 별도로
  보냅니다.

비교 기준을 "직전 원시 샘플"이 아니라 "마지막으로 실제 전송한 값"으로 잡은 이유는, 작은
변화가 여러 샘플에 걸쳐 누적되는 완만한 드리프트에 대해 매번 메시지를 보내는 것을 막기
위해서입니다 (완만한 드리프트는 어차피 1초 평균에 반영됩니다).

### 6. 센서 읽기 에러 보고 (연결 끊김과는 다른 장애)

AHT20/BMP280 각각은 **부팅 시 발견되었다고 해서 계속 정상 응답한다는 보장이 없습니다** —
배선이 흔들리거나, I2C 버스에 노이즈가 끼거나, 센서가 측정 도중 멈출 수 있습니다. 이 랩은
이 상황을 mbox 연결 자체가 끊기는 것과 **구분해서** 보고합니다.

- `sensor_mask`: 부팅 시 이 센서를 발견했는지 여부 (한 번 정해지면 이후 안 바뀜).
- `error_mask`: **이번 200ms 틱**에서 그 센서의 I2C 읽기가 실패했는지 여부 (매 틱마다
  갱신됨). 이 값이 이전에 M55에 보낸 값과 달라지는 순간 — 즉 센서가 새로 실패하기 시작하거나,
  실패하던 센서가 복구되는 순간 — `IPC12_REASON_SENSOR_ERROR` 메시지를 즉시 보냅니다
  (온도/기압 급변 알림과 똑같은 "즉시 알림" 방식).

M55는 이 두 정보를 화면에 **완전히 분리된 두 줄**로 보여줍니다.

- **연결 상태** (위쪽 줄): 2초 동안 M4로부터 mbox 메시지가 아예 안 오면 "LOST". M4가
  살아있는지, mbox/IPC 자체가 죽었는지를 나타냅니다.
- **센서 상태** (그 아래 줄): 마지막으로 받은 메시지의 `error_mask`를 그대로 보여줍니다.
  M4는 정상적으로 살아서 메시지를 계속 보내고 있지만, 그 안에 담긴 센서 값 중 일부가
  못 읽어온 것이라는 뜻입니다. `SENSOR OK`(초록), `AHT20 ERR`/`BMP280 ERR`(둘 중 하나만
  실패, 빨강), `SENSOR ERR`(둘 다 실패, 빨강) 네 가지로 표시됩니다.

이 둘을 하나로 합쳐 표시하면 "M4가 죽었다"와 "M4는 멀쩡한데 센서 하나가 죽었다"를 구분할
수 없게 되므로, 일부러 두 줄로 나눴습니다.

### 7. 센서 복구 (단순 재시도로는 부족한 이유)

처음 버전은 실패한 센서를 매 200ms 틱마다 그냥 다시 읽기만 시도했는데, 실기에서
"배선을 다시 연결해도 계속 ERR로 표시된다"는 문제가 확인됐습니다. 원인은 단순 재시도로는
해결되지 않는 두 가지 실제 I2C 하드웨어 동작 때문입니다.

1. **I2C 버스 자체가 물리적으로 멈출 수 있음**: 트랜잭션 도중 배선이 빠지면, 슬레이브(센서)가
   SDA 라인을 로우로 잡은 채로 멈춰버릴 수 있습니다. 이 상태에서는 배선을 다시 연결해도
   버스가 저절로 풀리지 않고, 이후의 모든 I2C 트랜잭션이 계속 실패합니다 — SCL을 몇 번
   더 클럭쳐서 슬레이브를 강제로 풀어주는 별도의 "버스 복구" 절차가 필요합니다.
2. **센서가 순간적으로 전원을 잃으면 설정을 잊어버림**: 배선을 뽑았다 꽂는 과정에서 VCC도
   같이 끊겼다면, AHT20/BMP280 모두 초기화 상태로 리셋되어 다시 초기화 시퀀스를 밟지 않는
   한 정상적으로 응답하지 않습니다.

그래서 이 랩은 특정 센서가 **연속으로 5틱(약 1초) 이상** 계속 실패하면, 다음 두 가지를
순서대로 시도한 뒤 실패 카운트를 리셋합니다.

- `i2c_recover_bus(i2c_bus)` 호출 — SCL을 수동으로 몇 번 더 토글해 멈춰있는 버스를
  강제로 풀어줍니다. 이 API를 지원하지 않는 I2C 컨트롤러도 있어서, 실패해도 로그만 남기고
  다음 단계로 넘어갑니다(치명적 에러로 취급하지 않음).
- 해당 센서의 초기화 시퀀스 재실행 — AHT20은 `aht20_init()`(소프트 리셋+초기화), BMP280은
  `bmp280_configure()`(`ctrl_meas`/`config` 레지스터 재설정)를 다시 호출해, 전원이
  순간적으로 끊겼다 들어온 경우에도 설정이 복원되도록 합니다.

이 복구 시도 이후에도 계속 실패하면(예: 배선이 여전히 빠져있는 경우) 다시 5틱을 세고
동일한 복구를 반복 시도합니다 — 즉 "배선을 완전히 복구하면 최대 약 1초 안에 자동으로
다시 정상 동작"하는 것이 이 설계의 목표입니다.

```
                                                     타임아웃 누적 2초: 연결상태=LOST
```

- **M4 (`lab/remote/src/main.c`, CLIENT)**: `&i2c0`에서 AHT20/BMP280을 부팅 시 스캔하고,
  200ms 주기로 두 센서를 읽어 평균/급변알림/에러알림 세 종류의 `struct ipc12_env_msg`
  메시지를 상황에 따라 mbox로 보냅니다.
- **M55 (`lab/src/main.c`, HOST)**: `rx_cb()`는 메시지를 큐에 넣기만 하고 즉시 반환합니다
  (SPI로 TFT를 그리는 작업은 블로킹성이라 ISR에서 직접 할 수 없음 — Lab 03/07/11에서 확립된
  규칙). `Display_Task` 워커 스레드가 큐에서 값을 꺼내 화면을 갱신하고, 별도로 500ms마다
  깨어나 마지막 수신 이후 2초가 지났는지도 검사합니다.

## 핀 연결 (하드웨어 배선)

이 랩은 두 갈래의 배선이 필요합니다 — **AHT20+BMP280 콤보 모듈**(M4가 읽음)과 **ST7789V3
TFT 패널**(M55가 구동, Lab 11과 완전히 동일한 배선)입니다.

### AHT20+BMP280 콤보 모듈 (I2C0, M4)

| 신호 | SoC 핀 | devicetree 프로퍼티 |
|---|---|---|
| I2C0 SCL | SR110_GPIO3 | `i2c0_ms_scl` pinctrl (bias-pull-up 적용) |
| I2C0 SDA | SR110_GPIO4 | `i2c0_ms_sda` pinctrl (bias-pull-up 적용) |
| VCC | 모듈 데이터시트에 표기된 전압(대개 3.3V) | — |
| GND | 공통 | — |

I2C0은 SPI0/UART0/UART1이 공유하는 핀 그룹과 완전히 독립된 자신만의 핀 그룹(SoC의
LPS_GEAR1 멀티플렉스 슬롯)에 있어서, Lab 11의 SPI0-vs-콘솔 충돌 같은 문제가 여기서는
발생하지 않습니다. 또한 I2C1(온보드 가속도계/GPIO 익스팬더/카메라가 물려 있는 버스)과도
완전히 별개의 컨트롤러이므로, 이 랩은 다른 랩들이 항상 하는 "M55에서 &i2c1 disable" 같은
조치가 굳이 필요하지 않습니다 (다만 커리큘럼 전체의 일관성을 위해 오버레이에는 그대로
남겨뒀습니다).

AHT20/BMP280 콤보 모듈은 대부분 3.3V 전원으로 동작합니다. 사용 중인 모듈의 데이터시트에서
정확한 동작 전압을 확인하고, 만약 SR110의 GPIO3/4 핀 자체가 3.3V가 아닌 다른 로직 레벨로
동작한다면(레벨 미스매치가 있다면) Lab 11의 TFT처럼 레벨 시프터가 필요할 수 있습니다 —
실기 배선 전 반드시 전압을 먼저 확인하세요.

### ST7789V3 TFT 패널 (SPI0, M55) — Lab 11과 동일

이 부분은 Lab 11에서 이미 검증된 배선을 그대로 재사용합니다. 이 랩만 보고도 배선할 수
있도록 여기 다시 정리합니다.

**⚠️ 레벨 시프터가 반드시 필요합니다.** SR110의 SPI0/GPIO 패드는 **1.8V I/O**로 동작하는데,
일반적으로 유통되는 ST7789V3 모듈의 IOVCC는 3.3V이고, 이 모듈이 로직 하이로 인식하는 최소
전압(VIH ≈ 0.7 × IOVCC ≈ 2.31V)을 1.8V 신호는 넘지 못합니다. 레벨 시프터 없이 직결하면
**SPI 통신 자체는 에러 없이 끝나는데 화면은 계속 검게만 나오는** 증상이 나타납니다. 아래
5개 신호 전부 양방향 레벨 시프터를 거쳐야 합니다.

| 신호 | 방향 | 비고 |
|---|---|---|
| SCLK | M55 → 패널 | 계속 토글되는 클럭 신호 |
| MOSI | M55 → 패널 | |
| CS | M55 → 패널 | 하드웨어 네이티브 CS (별도 GPIO 아님) |
| RST | M55 → 패널 | |
| DC | M55 → 패널 | |

검증된 레벨 시프터 모듈: **TXS0108E** (자동 방향 감지형). TXS0108E는 SCLK처럼 빠르게 계속
토글하는 신호에는 완벽하게 맞는 부품이 아니어서, `spi-max-frequency`를 4MHz로 보수적으로
설정했습니다. MISO는 이 패널이 쓰기 전용이라 배선하지 않아도 됩니다.

| 신호 | SoC 핀 | 헤더 위치 | devicetree 프로퍼티 |
|---|---|---|---|
| SPI0 CLK | SR110_GPIO22 | J25 (Left 20pin) | `spi_mstr_clk` pinctrl |
| SPI0 MOSI | SR110_GPIO23 | J25 (Left 20pin) | `spi_mstr_mosi` pinctrl (M55 UART1 TX와 공유) |
| SPI0 MISO | SR110_GPIO24 | J25 (Left 20pin) | `spi_mstr_miso` pinctrl (배선 불필요) |
| SPI0 CS | SR110_GPIO21 | J25 (Left 20pin) | `spi_mstr_cs` pinctrl (하드웨어 네이티브 CS) |
| RESET | SR110_GPIO17 | J24, 3번 핀 | `reset-gpios = <&gpioa 17 GPIO_ACTIVE_LOW>` |
| DC | SR110_GPIO18 | J24, 4번 핀 | `dc-gpios = <&gpioa 18 GPIO_ACTIVE_HIGH>` |
| VCC | 3.3V (패널 쪽 레벨 시프터 HV 레일) | — | — |
| GND | 공통 | — | — |

SPI0가 M55 콘솔(UART1, GPIO23/24 공유)을 가져가므로, 이 랩에서도 Lab 11처럼 **M55 콘솔은
포기**하고 TFT 화면 자체를 출력 수단으로 씁니다.

## devicetree 설정

### M4 오버레이 (`lab/remote/boards/sr100_rdk_sr100_m4.overlay`)

```dts
#include <zephyr/dt-bindings/i2c/i2c.h>

&ipc0 {
	shared-memory-size = <0x400>;
};

&i2c0_ms_scl {
	bias-pull-up;
};

&i2c0_ms_sda {
	bias-pull-up;
};

&i2c0 {
	status = "okay";
	pinctrl-0 = <&i2c0_ms_scl &i2c0_ms_sda>;
	pinctrl-names = "default";
	clock-frequency = <I2C_BITRATE_STANDARD>;
};
```

I2C0은 기본적으로 `status = "disabled"`이고 default pinctrl-0도 없는 상태로 시작하므로,
버스 활성화와 핀 그룹 지정을 여기서 명시적으로 다 해줘야 합니다. 센서 자식 노드
(`aht20@38 { ... }` 같은)는 일부러 선언하지 않았습니다 — 주소를 부팅 시 스캔으로 찾기
때문에, 고정 주소를 전제하는 devicetree 자식 노드 방식과는 맞지 않습니다.

### M55 오버레이 (`lab/boards/sr100_rdk_sr100_m55.overlay`)

```dts
&i2c1 { status = "disabled"; };
&gpio_exp0 { status = "disabled"; };
&ov02c10 { status = "disabled"; };

&ns16550_uart1 {
	status = "disabled";
};

&spi0 {
	#address-cells = <1>;
	#size-cells = <0>;
	status = "okay";
	pinctrl-0 = <&spi_mstr_mosi &spi_mstr_miso &spi_mstr_clk &spi_mstr_cs>;
	pinctrl-names = "default";

	st7789v_disp: st7789v@0 {
		compatible = "zds,st7789v";
		reg = <0>;
		spi-max-frequency = <4000000>;
		reset-gpios = <&gpioa 17 GPIO_ACTIVE_LOW>;
		dc-gpios = <&gpioa 18 GPIO_ACTIVE_HIGH>;
		width = <240>;
		height = <280>;
		x-offset = <0>;
		y-offset = <20>;
	};
};
```

`zds,st7789v`는 Zephyr 표준 바인딩이 아니라 Lab 11에서 정의한 커스텀 바인딩이며, 이 랩도
그 정의(`lab/dts/bindings/display/zds,st7789v.yaml`)를 그대로 복사해서 씁니다. devicetree
컴파일러가 이 파일을 찾을 수 있도록 `lab/CMakeLists.txt`에서 `find_package(Zephyr...)`보다
먼저 `DTS_ROOT`에 이 앱의 경로를 추가해야 합니다.

```cmake
list(APPEND DTS_ROOT ${CMAKE_CURRENT_SOURCE_DIR})
find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
```

I2C1(M4가 소유)을 비활성화하는 것은 이 커리큘럼 전 랩의 공통 패턴이지만, 이 랩의 센서는
I2C0에 있으므로 사실 M55 쪽에서 I2C1을 건드릴 이유가 없습니다 — 다만 다른 랩들과의 일관성
유지 차원에서 그대로 남겨뒀습니다.

### prj.conf

M4(`lab/remote/prj.conf`)는 센서 서브시스템을 안 쓰므로 `CONFIG_I2C`만 있으면 됩니다.

```
CONFIG_MBOX=y
CONFIG_I2C=y
CONFIG_LOG=y
CONFIG_LOG_DEFAULT_LEVEL=3
CONFIG_PRINTK=y
```

M55(`lab/prj.conf`)는 Lab 11과 동일합니다 — in-tree 디스플레이 드라이버를 안 쓰므로
`CONFIG_DISPLAY`/`CONFIG_CHARACTER_FRAMEBUFFER`/`CONFIG_ST7789V` 없이 SPI/GPIO만
있으면 됩니다.

```
CONFIG_MBOX=y
CONFIG_SPI=y
CONFIG_GPIO=y
CONFIG_MAIN_STACK_SIZE=4096
CONFIG_UART_CONSOLE=n
CONFIG_CONSOLE=n
CONFIG_LOG=y
CONFIG_LOG_DEFAULT_LEVEL=3
CONFIG_PRINTK=y
```

`CONFIG_UART_CONSOLE=n`/`CONFIG_CONSOLE=n`이 필요한 이유: `ns16550_uart1`을 devicetree에서
비활성화했는데 보드 defconfig가 기본으로 켜는 `CONFIG_UART_CONSOLE=y`가 남아있으면
`SERIAL_HAS_DRIVER=n`과 충돌해 Kconfig 단계에서 빌드가 실패합니다. (`CONFIG_SERIAL=n`을
직접 끄면 안 됩니다 — 이 SoC의 Kconfig가 `SOC_SR100_M55`에서 `SERIAL_SUPPORT_ASYNC`를
무조건 y-select하기 때문에 `SERIAL=n`과 충돌해 또 다른 방식으로 빌드가 깨집니다.)

## 빌드 방법

west 워크스페이스 루트(`zephyr/`가 보이는 디렉터리)에서 실행합니다.

```bash
# 1) M4(remote) 먼저 빌드
west build -p always -b sr100_rdk/sr100/m4 ./zephyr_ipc_sr110/12_aht20_bmp280_logging/lab/remote -d m4

# 2) M55(host, M4 바이너리를 M4_BUILD로 포함) 빌드

```

`M4_BUILD`는 M55 빌드 디렉터리(`-d m55`) 기준 상대 경로입니다. `m4/`, `m55/`가 워크스페이스
루트 아래 형제 디렉터리인 배치라면 `../m4`가 맞습니다.

## 실행 및 결과 확인

이 랩도 M55 콘솔을 못 쓰므로, **M4 콘솔만** 외부 USB-to-TTL로 연결해 확인합니다(J24 13/14번
핀, 230400bps). M4 콘솔에는 부팅 시 센서 스캔 결과(`AHT20 found at 0x38`,
`BMP280/BME280 found at 0x76` 등)와 이후 급변/에러 이벤트 로그가 찍힙니다.

TFT 화면은 부팅 직후 "LAB12 ENV" 제목이 노란색으로 표시되고, 이후 M4로부터 메시지를 받을
때마다 아래 형태로 갱신됩니다.

```
LAB12 ENV
[■] OK          <- 연결 상태 (초록/회색/빨강 아이콘 + 텍스트)
[■] SENSOR OK   <- 센서 상태 (초록: 정상 / 빨강: AHT20 ERR·BMP280 ERR·SENSOR ERR)
T:23.5C         (빨간색, AHT20 없거나 실패 시 "T:23.5C(bmp)" 또는 "T:ERR")
H:45.2%         (초록색, AHT20 없거나 실패 시 "H:N/A" 또는 "H:ERR")
P:1013.2hPa     (청록색, BMP280 없거나 실패 시 "P:N/A" 또는 "P:ERR")
```

센서 모듈의 배선을 일부러 흔들거나 뽑아보면(예: SDA 라인을 순간 분리), 몇백ms 안에 해당
센서 값이 `ERR`로 바뀌는 것을 확인할 수 있습니다 — 이것이 2초 연결 타임아웃과는 별개로,
훨씬 빠르게 개별 센서 이상을 알려주는 이 랩의 핵심 동작입니다.

## 정리

- 실제 하드웨어 모듈은 부품 개체차/배선 방식에 따라 I2C 주소가 달라질 수 있으므로, 고정
  주소를 devicetree에 박아넣기보다 부팅 시 스캔하는 편이 더 견고할 때가 있습니다.
- 여러 센서가 같은 물리량(이 경우 온도)을 측정할 수 있을 때는, 하나가 실패해도 다른 것으로
  대체하는 fallback 설계로 가용성을 높일 수 있습니다 — 다만 화면에는 "어느 센서에서 온
  값인지"를 반드시 표시해 혼동을 막아야 합니다.
- "주기적 평균"과 "급변 시 즉시 알림"을 함께 설계하면, 노이즈에는 안정적이면서도 실제
  변화에는 빠르게 반응하는 시스템을 만들 수 있습니다.
- **연결이 끊긴 것**과 **연결은 되어 있는데 값을 못 읽는 것**은 서로 다른 장애이고, 사용자
  에게도 서로 다르게 보여줘야 문제 해결이 빨라집니다.

## 알아두면 좋은 점 / 남은 제약

1. **BMP280 보정(compensation) 공식**: Bosch 공개 데이터시트의 정수 연산 공식을 그대로
   옮겼고, 실기 검증에서 정상 동작을 확인했습니다. 값이 비정상적으로 나오는 경우가 생기면
   `bmp280_compensate_temp/pressure()`의 `dig_*` 계수 읽기부터 확인하세요.
2. **AHT20/BMP280 I2C 주소 자동 스캔**: AHT20은 고정 주소(0x38)만 프로브하고, BMP280은
   0x76/0x77 두 후보만 시도합니다. 모듈이 다른 주소를 쓴다면 `bmp280_candidates[]` 배열에
   추가해야 합니다.
3. **센서 에러 판정 기준**: 지금은 매 200ms 틱에서 I2C 트랜잭션 자체의 성공/실패만으로
   에러를 판단합니다. 값은 읽히지만 명백히 비정상(예: 기압이 0으로 나오는 등)인 경우까지
   에러로 잡지는 않으므로, 이런 상황이 관찰되면 판정 로직 보강이 필요할 수 있습니다.
4. **`i2c_recover_bus()`가 "SDA Stuck Low" 상태까지는 못 풉니다 (실기 확인됨, 미해결)**: 센서
   전원을 강제로 뺐다 꽂아 재현해본 결과, 이 SoC의 `i2c_dw` I2C 컨트롤러 드라이버가 버스가
   완전히 막힌 상태(`SDA Stuck Low`)를 자체적으로 감지하면, 이 랩의 `i2c_recover_bus()` +
   센서 재초기화 시도만으로는 복구되지 않는 것을 확인했습니다. 원인 분석과 다음에 시도해볼
   방향은 [트러블슈팅 문서](12_aht20_bmp280_logging_troubleshooting_kr.md)에 정리해뒀습니다.
   짧은 배선 흔들림 정도의 가벼운 글리치는 여전히 이 재시도 로직으로 복구됩니다.
